# Stage 1 — API Integration, Security & End-to-End Verification Guide

## 1. xAI Responses API Integration (`packages/ai`)

- **Endpoint**: `POST ${XAI_BASE_URL}/responses` (default `https://api.x.ai/v1/responses`)
- **Authentication**: Server-side header `Authorization: Bearer ${XAI_API_KEY}`
- **Payload Fields**:
  - `model`: Configured via `XAI_TEXT_MODEL` (overridable in **Settings -> AI Model & API** or the Chat header)
  - `instructions`: Generated by `buildMjSystemPrompt()` (`packages/ai/src/systemPrompt.ts`), enforcing Section 01 personality, 10 behaviour rules, English/বাংলা/Banglish responsiveness, and honest Stage 1 boundaries
  - `input`: Recent completed turns from SQLite (`[{ role: 'user' | 'assistant', content }]`)
  - `reasoning`: `{ effort: 'low' | 'medium' | 'high' | 'xhigh' }`
  - `max_output_tokens`: Configurable (default `4096`)
  - `stream`: `true` (SSE `response.output_text.delta` / `response.completed`) or `false`
  - `store`: `false` (local-first conversation persistence in SQLite)

## 2. Backend Endpoints (`apps/server`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `GET` | `/api/health` | Public | Backend, SQLite ping, AI key status (boolean only), active model |
| `GET` | `/api/auth/session` | Public | Current HttpOnly session & passcode requirement status |
| `POST` | `/api/auth/login` | Public (rate-limited) | Issues HMAC-SHA256 signed `HttpOnly` cookie (`mj_session`) |
| `POST` | `/api/auth/logout` | Public | Clears `mj_session` cookie |
| `GET` | `/api/conversations` | Session | List & search (`?q=`) conversations |
| `POST` | `/api/conversations` | Session | Create a new conversation |
| `GET` | `/api/conversations/:id` | Session | Load conversation & ordered messages |
| `PATCH` | `/api/conversations/:id` | Session | Rename conversation |
| `DELETE` | `/api/conversations/:id` | Session | Delete conversation & cascade messages |
| `POST` | `/api/conversations/:id/messages` | Session | Persist user turn & stream Grok SSE response |
| `POST` | `/api/conversations/:id/regenerate` | Session | Regenerate last assistant turn via SSE |
| `GET` / `PATCH` | `/api/settings` | Session | Read/update model, reasoning, UI & budget settings |
| `GET` | `/api/usage` | Session | Today & monthly token usage, estimated spend, recent events |

## 3. Centralized Error Codes (`packages/shared`)

All API, network, database, auth, validation, and budget failures normalize to `StructuredErrorPayload`:
- `INVALID_API_KEY`, `UNAUTHORIZED`, `RATE_LIMITED`, `INSUFFICIENT_CREDITS`, `INVALID_REQUEST`, `MODEL_UNAVAILABLE`, `UPSTREAM_ERROR`, `TIMEOUT`, `NETWORK_DISCONNECTED`, `BUDGET_EXCEEDED`, `DATABASE_UNAVAILABLE`, `DATABASE_TIMEOUT`, `DATABASE_QUERY_ERROR`, `DATABASE_MIGRATION_ERROR`, `VALIDATION_ERROR`, `NOT_FOUND`, `ABORTED`, `INTERNAL_ERROR`.
- Transient retryable failures (`RATE_LIMITED`, `UPSTREAM_ERROR`, `TIMEOUT`, `NETWORK_DISCONNECTED`) retry up to 2 times using exponential backoff with full jitter before first token emission.

## 4. Manual End-to-End Checklist

1. **Missing-key safety**: Leave `XAI_API_KEY=your_xai_api_key_here`, start `npm run dev`, open `http://127.0.0.1:5173`. Confirm status shows `API Key Missing` and sending a message displays a clean `[INVALID_API_KEY]` guidance banner.
2. **Browser secret isolation**: Open Browser DevTools -> Network & Sources, inspect `/api/health` and `/api/settings` payloads and `apps/web/dist/assets/*.js`. Verify `XAI_API_KEY` never appears anywhere in the browser.
3. **Live streaming & history**: Set a real `XAI_API_KEY` in `.env`, restart `npm run dev`, send a prompt in English and a follow-up in Banglish (`Amar ekta portfolio website plan dorkar`). Verify token streaming, markdown code copy button, orb animation during streaming, and persistence across page refresh.
4. **Stop & Regenerate**: Start a long response, click **Stop**, confirm partial text is kept with `Stopped`, then click **Regenerate** and verify replacement.
5. **Rename, Search & Delete**: Rename a conversation in Chat, search for it, then delete it.
6. **Budget Caps**: In **Settings -> Usage & Budget**, verify today/month metrics match requests and test soft/hard budget thresholds.
